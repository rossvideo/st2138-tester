# Test-Your-Catena

Node 24 Express app for validating SMPTE ST 2138 Catena devices over REST or gRPC.

## Architecture

`src/server.ts` serves the browser UI and mounts API routes. Routes delegate device operations to worker processes and service modules; `src/validation/` adapts the vendored ST 2138-a validator. `npm run build` compiles `src/` to `dist/` and copies `src/ui/` into `dist/ui/`.

## Validation diagnostics

- Validate against the matching vendored schema when one exists. Read Param uses `component_param`; Connect uses `push_updates` and validates its submembers separately.
- Name the schema or rule in each diagnostic, show a ✅/❌ result and relevant warnings or errors, and keep full definitions inside **Validator details**.
- Keep Connect output to one compact diagnostic per streamed chunk, with separate indented submember checks. Manual Connect results keep submember checks as individual entries in each chunk's `submembers` array.

## Commands

Use Node.js 24. From the repository root:

```sh
npm ci
npm run dev
npm test
npm run build
npm audit --audit-level=moderate
```

Run one test:

```sh
node --import tsx --test --test-name-pattern='sets a different writable value and restores the original' tests/member-checks.test.js
```

There is no lint script. CI runs tests and build in `.github/workflows/tests.yml`; the audit command is in `.github/workflows/codeql.yml`.

## Boundaries

- `vendor/st2138-a/` is a git submodule; do not hand-edit its contents. Initialize it with `git submodule update --init --recursive`. Intentional validator updates change the submodule pointer; keep `version.md` in sync with `vendor/st2138-a/VERSION`.
- `dist/` is generated by `npm run build`; change sources in `src/`, not generated output.

## Conventions

TypeScript in `src/` uses strict checking (`tsconfig.json`); `npm run build` enforces it.

## Guardrails

- Device scans can write parameter values and attempt restoration. Preserve restore-and-verify behavior; a failed SET may still have changed the device. Only test devices you are authorized to use.
- Keep JWTs out of logs and persisted reports. Preserve report redaction, default TLS certificate/hostname verification, and explicit opt-in for insecure TLS.
- Do not expose this app directly to the Internet without authentication, access controls, and restricted outbound destinations. Manual mutating requests must remain individually user-triggered and confirmed.
